## 用户补充：星露谷式真实地图视觉

本轮过程中用户进一步明确“真实地图但是改成星露谷样式”。采用《星露谷物语》式温暖像素乡野表达：像素水纹、草地颗粒、树冠、屋顶材质与 Q 版角色。原型使用原创代码绘制，不复制游戏角色、素材或地图。道路、河岸、公园和建筑轮廓保留真实坐标；树冠只是公园内风格化装饰，不是实测树木/地点，屋顶纹理不声称对应真实建筑外观。此补充是视觉要求，不授权虚构真实路网、增加游戏任务/奖励或更换地图供应商。

## 具体布局、视觉与交互

手机按 375×812 打样；桌面按约 1280px 宽打样。地图始终占满视口，角色层独立于底图缩放。正文、输入、提示及中文保持矢量/真实文字，不整屏像素化。

- 顶部：克制 Space 名称、本人示例头像/账户入口、语言切换；不放 unread、关系指标或排行榜。
- 地图：真实街区与两位 Resident；减少无关 POI，保留河流、公园和桥名；不使用卫星图、雷达、夜光线路、玻璃效果或厚重阴影。
- 边缘：双人快捷定位/查看；缩放、回到关注区；地图可拖动，方向键和 `+`/`-` 可替代手势。两人远隔时切换各自街区，不强行缩成世界全图。
- 底部：单一“留一点今天”主操作及不带地点的生活入口；回放说明与跳过不阻断地图操作。
- 点击角色或生活针在地图上打开轻量详情，关闭或 Escape 后镜头不重置。原型使用原生 dialog 管理键盘焦点。
- 原型始终显示“交互原型 / 模拟位置变化”，调试场景放进“原型实验台”，不得迁入生产按钮组。
- 地图渲染用连续帧移动镜头；8 帧角色步态约每 100ms 更新。两套节奏独立，不让地图随角色低帧率卡顿。

颜色是**候选**而非已批准品牌色：面板 `#FFF4DF`、地面 `#E8DCC4`、公园 `#B8D1A4`、水域 `#AECFE0`、正文 `#3E3831`。实现增补 `#665A4D` 次级文字、`#536B46` 主操作、`#23586D` focus；实际对比度见验证记录。交互目标至少 44×44 CSS px；角色画面约 40–44px 宽、64–70px 高，外部命中区至少 60px 宽，接近建议的 48–64px 量级且不会随地理缩放无限变大/消失。可见 focus、文本状态和双语可访问标签均为必需。

角色是原创棕发赭衣“小林”和深发绿衣“小雨”，不使用真人照片或第三方角色。原型为代码原生 SVG：阶梯发型/服装轮廓配柔和眼睛和嘴；此资源方式不是生产头像生成技术的锁定。正式角色方向可扩为正/侧/背面共享身份参考的动作集，生产前需逐帧检查身份与朝向。

## 身份、Presence 与地图标记

持久身份建议使用受 Space 授权的资源版本及 Resident 已确认资源指针；生成候选不覆盖已确认版本。更换身份须本人再次确认。资源、位置样本和共享权限记录只能是支撑性记录，不能建立 Avatar、Map 或 Movement 核心产品实体。

Presence 继续表示本人自愿留下的“今天的我”，遵循已验收 viewer-local-day freshness。位置更新不能更新 `Presence.updatedAt`、不能写入 `shortText`、不能自动推断情绪/状态。“在看书”不等于“在图书馆”。跨日或 clear 后停止旧状态动作，回到中性，同一个角色保留。

| 展示对象                | 来源与语义                                   | 出现/消失及权限                                                                                      |
| ----------------------- | -------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Resident 角色位置       | 当前仍获本人共享许可且质量有效的允许展示坐标 | 不可访问/暂停/撤销/过期则隐藏地理位置，身份仍在快捷入口可查看；不显示旧坐标暗示当前在场              |
| Presence 动作           | 自愿且当天有效的状态；独立于坐标             | clear/跨日回中性；不因位置回放刷新状态日期                                                           |
| LifePoint 生活针        | 主动附带可选地点的记录，不是 GPS 事件        | 遵循内容 visibility/移除/Space 边界；无地点保留自然内容入口，不虚拟安排到某坐标                      |
| Response / SharedMoment | 原记录被接住的领域关系                       | 未来在详情接住并形成 SharedMoment；不靠计数、红点或颜色奖励表达；同一 LifePoint 不复制成多个地图实体 |
| Visit                   | 已有 SharedMoment 的重访入口                 | 简单日期分组与原地点可选视图，访问规则与原内容一致；不显示“对方几点看过”                             |

后两项是具体集成建议，等待对应 Phase 的内容可见性与 lifecycle 收口。本轮示例内容不进入生产导航和数据库。

## 移动判断与回放契约（可测试）

处理流水线：**被定位者授权采集 → 服务端接收/质量校验 → 查看者读取已授权样本 → 判断可信新变化 → 展示**。查看者打开页面只触发读取/展示，不会在另一设备上开启采集，更不会补出从未记录的轨迹。小人走动是表达语言，不证明交通方式为步行。

支撑样本建议至少包含 opaque id、Resident/Space 所属、共享代次 epoch、坐标、采集时间、accuracy、来源和服务器接收时间；服务端按 session 推导采集主体，拒绝替别人上报。与 Presence 时间戳分离。建议明确“最后可展示位置”，不用“实时位置”掩盖采集/上传延迟。

| 状态               | 条件                                    | 表现                                             |
| ------------------ | --------------------------------------- | ------------------------------------------------ |
| SHARING_PAUSED     | 暂停、撤销或访问不再成立，优先于缓存    | 停止播放并移除旧位置/路径，不再读取新的变化      |
| INSUFFICIENT_DATA  | 无样本、过期、差精度、异常或不可信缺口  | “暂时没有可展示的位置更新。”；不推论对方没移动   |
| NO_BASELINE        | 仅一个有效位置                          | 直接显示允许的终点，不虚构屏外/旧起点            |
| NO_CHANGE          | 有效数据未支持新变化                    | 保持静止，不因打开、语言切换或重渲染播放         |
| MOVEMENT_AVAILABLE | 质量/权限检查通过，存在未呈现的有效变化 | 准备短回放，检查 reduced-motion 和查看者关闭偏好 |
| REPLAYING          | 显示新变化中                            | 约 3 秒原型参数，可跳过，动画不锁住地图操作      |
| SETTLED            | 完成/跳过/静态表达/同段已处理           | 最后可展示状态；完成/跳过写查看者自身游标        |

### 样本质量与路线真实性

1. 先查成员资格、本人共享许可和 epoch；暂停/恢复产生新 epoch，不拼接授权空档。
2. 检查坐标范围、有限数值、accuracy、时间、过期与重复 id；按可信时间顺序处理。重复不产生段，乱序不反向移动。质量不良点断开链条，不跨缺口连接；尾点不可用时原型保守隐藏位置。
3. 经纬度浮点差异不等于移动。原型条件为 `distance > max(minMeters, accuracyA + accuracyB)`；同时检查时间间隔和异常速度。真实设备误差可能相关，这个模型只是打样，不能宣称已校准。
4. 仅起终点用虚线“位置变化示意”，即使穿过建筑也不能当真实路径；不调用导航拼接路线。中间样本只能沿有效采样段画实线，实线仍需标明是采样近似而非连续真值。原型全部是合成演示。
5. 无有效变化只说“有效样本未支持新的位置变化”，不是保证对方没移动；无新数据必须用不确定状态。越过 freshness 窗口后重新评估，禁止无限保留旧坐标冒充当前。
6. 长距离不用跨海跑动。建议先说明地点变化，再直接切换目标街区镜头，使用静态前后地点或短淡变；reduced-motion 直接切换。原型远距场景保留伦敦街区与“巴黎底图未打包”的诚实空态，不虚构第二城市底图。

所有过滤参数集中在 `movement.mjs` 的 CONFIG：18m 最小差异、60m 最大误差、15min freshness、5min 最大采样间隔、70m/s 异常速度、3km 长距界限、3s 回放、最多 3 个段。**全部为合成场景参数、待实测校准，不是获批的生产精度、采集频率、保留期限或真实移动标准。** 生产校准须覆盖室内外、城市遮挡、静止噪声、多交通方式、断网与设备省电模式。

### 去重、多段与生命周期

同一变化默认自动展示一次。完成、主动跳过或选择静态等价后记录查看者本人的处理游标；刷新和中英文切换不得重播。原型 key 按 demo account / demo Space / epoch 隔离，只存段 id，不存照片或真实轨迹，不发给另一方。无法持久化时保守使用静态表达。原型重置游标按钮仅用于验证，不属于生产功能。

生产建议：游标是查看者私有 UI 状态，服务端不得向对方暴露为位置已读；账户退出清理本地授权缓存，账户/Space 切换使用不同存储域；处理游标和可访问性分开，已处理不等于仍有权看。缓存命中、重新打开、恢复前台及播放过程中收到权限变化时都须重新验证；离开 Space 后立即拒绝读取，清除本地可见位置与路径。撤销时在线客户端立刻中断；离线客户端无法获知撤销，建议失去授权新鲜性就停止敏感缓存展示，服务器下一次访问必须拒绝。不能承诺抹除用户已保存的截图。

**多段设计建议：**在有限窗口内按有效连续段判断，保留 A→B→A 的往返；最多选最近 3 段、总回放不超过 4 秒，用“最近一小段变化”说明取样，有省略时明确不是完整路线。未选择的旧段标记为本轮已处理而不是“已观看”，不积压为强制队列。中间缺口不连接，转场到下一段起点需静态说明。原型 `omitted` 数量只在实验台输出，不作为正式未读计数。退出/页面隐藏时原型结束当前短回放并处理游标；生产中断恢复策略须与隐私复查一致。

## 隐私与外部请求边界

允许的是**本人知情、自主控制**的位置共享表达；这修订旧规格中对地理共享未决定的部分，不改变无感监控、last-seen、关系压力与行为推断的禁令。

- 开启：默认关闭，由被定位的本人主动进入说明页，独立确认接收者、精度、后台选项和期限；OWNER/伴侣无代开权限。OS 地理权限不等于产品共享许可，两者均须成立。
- 暂停：停止采集/上传及向对方展示位置；恢复开启新 epoch，不能推断暂停期间路线。拒绝或暂停不阻断 Home/核心生活闭环，不提供催对方开启按钮。
- 撤销：停止采集和访问、使回放缓存失效、触发所选位置数据删除。退出 Space 后服务器立即阻断原成员位置访问；原共同生活内容按已批准独立生命周期处理，不自动级联删除。
- 精度建议：默认采用可理解的街区级最小必要精度；若要演示一条街上的可信移动，需用户选择更精确共享并接受暴露范围。先过滤/模糊化，再给地图和动画使用，不能从精确回放反推已选择隐藏的细节。最终数值未批准。
- 保存建议：第一版先保留当前允许位置及短时变化窗口，不建立永久精确轨迹档案；是否保留中间点、窗口时长、备份清除时限必须在采集实施前批准并可验证自动删除。原型 15min 是 freshness 参数，不是存储期限批准。
- 自拍与位置授权分开。建议原图仅用于单次生成、确认后尽快删除原图及未选候选；最终资源按身份版本保留，替换/撤回有删除传播。具体 provider、训练使用、地域、期限、费用与失败处理仍待批准。
- 默认不把 Presence、自拍、LifePoint、Response、SharedMoment 或轨迹发给外部 AI。位置样本不自动生成 LifePoint/SharedMoment，不放进 `Presence.shortText`。
- 禁止普通日志/分析事件/公开 URL 记录精确位置、原照片、认证秘密。用于去重的段 id 应 opaque，不能把坐标塞进标识符。

原型运行只向本地服务器读取打包文件；不使用地图 SDK、外部字体或 analytics，`Permissions-Policy` 禁止 geolocation/camera/microphone，CSP 只允许本地连接。地图归因链接仅在用户主动点击时访问 OSM。开发时获取的是公开伦敦 bbox，不是用户住址/设备位置。

生产 provider 会收到 IP、时间、请求的瓦片区域/zoom（可能推断所看位置）；若使用 geocoding、directions 或 SDK geolocation，可能收到查询地点/坐标及设备信息。建议自托管或受控代理最小化第三方视野，但会增加数据更新、运维、许可和成本负担；代理不是自动匿名保证。provider、日志/缓存、数据地域与费用须单独审查。Google Maps 仅作为比较选项，未选定；公开 OSM 数据也不代表无限免费的生产瓦片服务。

## Web 与后台定位：官方能力证据

证据读取日期：2026-09-04 本地。W3C 规定位置更新面向 fully-active 且 visible 的文档，接口暴露在 Window；Chrome 说明隐藏页可能冻结/丢弃，冻结时 JS timer/fetch callback 不执行。[W3C Geolocation §6](https://www.w3.org/TR/geolocation/)、[Chrome Page Lifecycle](https://developer.chrome.com/docs/web-platform/page-lifecycle-api)。因此安装 PWA 或增加 Service Worker 不能提供持续后台定位保证。

Apple 文档页面通过本轮文本工具仅显示 JavaScript 壳；已通过官方搜索索引核实背景更新说明及 `CLBackgroundActivitySession` 的授权用途，未声称已完整执行平台示例。[Apple 后台定位](https://developer.apple.com/documentation/corelocation/handling-location-updates-in-the-background)、[CLBackgroundActivitySession](https://developer.apple.com/documentation/corelocation/clbackgroundactivitysession-3mzv3)。Android 官方说明后台位置受权限及系统限制，Android 8+ 普通后台应用可能每小时仅收到几次更新。[Android background location](https://developer.android.com/develop/sensors-and-location/location/background)。

| 被定位方的设备状态    | 当前 Next.js Web/PWA 的可保证范围                                            | 具备原生定位能力的客户端                                                      |
| --------------------- | ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 页面前台可见          | 在安全上下文、OS/浏览器及本人共享许可下可以申请读取/订阅；仍会失败或精度不足 | 可按平台授权请求更新                                                          |
| 页面隐藏/切到别的 App | 不保证持续采集，不能据此形成完整后台轨迹                                     | 需后台模式、平台许可和服务配置；受系统调度/省电影响                           |
| 手机锁屏              | 不保证；必须允许缺口和过期                                                   | 获批后台能力可支持特定场景，需真机验证频率/中断                               |
| 页面或浏览器关闭      | 页面采集结束，Service Worker 不是 Geolocation 后台替代                       | App 被系统终止或用户强制关闭的行为取决于 API/OS；不能承诺强制关闭后仍持续记录 |
| 原生 App 后台运行     | Web 本身不具备对应原生授权与执行环境                                         | 可申请完整工作包；不是获权后无限、实时、无缺口的保证                          |

查看者关闭 App 并不必然阻止被定位方已获授权的原生客户端继续上传；查看者再次打开只能读取已经保存且仍可访问的样本。**被定位方关闭 Web 页面**时没有可靠的新采样来源；查看者打开自己的网页无法取得对方设备位置。

区分三类限制：

- **技术不可保证：**当前 Web/PWA 隐藏、锁屏、关闭后的持续采集与完整路线。
- **暂未实现：**前台采集、共享权限服务、样本质量处理、生产地图与头像资源管线；本轮只是原型。
- **需要额外授权：**外部 AI/自拍处理、生产 provider、精度/频率/保留/删除、后台采集和原生客户端范围修订。

可真实交付的有限 Web 工作包为：本人前台可见时明确开启的有限更新、服务端安全保存获批范围、查看者读取有效历史变化、诚实无数据/暂停/静态等价。它不能被称为完整后台体验。

满足完整目标需要移动端工作包：iOS Core Location 权限与后台 session、Android 权限/合适的前台或后台服务、明确可见的采集控制、加密离线队列及删除、断网重传去重、epoch/服务端授权、低电量/锁屏/强制关闭真机矩阵、商店披露及电量预算。原 Master Spec 排除未经批准的 native applications，因此必须取得范围修订；本轮不创建原生工程，不把目标改成“双方一直开网页”。
